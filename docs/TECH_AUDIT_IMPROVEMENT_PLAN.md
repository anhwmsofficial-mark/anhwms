# Technical Audit Improvement Plan

## 목표

외부 기술 감사 TOP 30 항목을 스타트업 단계에 맞는 MVP 우선순위로 정리하고, 운영 사고 위험이 큰 항목부터 작은 배치로 개선한다.

## 진행 원칙

- 운영 화면의 거짓 데이터 노출, 인증/권한 누락, 데이터 정합성 위험을 최우선으로 처리한다.
- 대규모 리팩터링보다 라우트 보호, 표준화, 검증, 문서화를 먼저 적용한다.
- 각 배치는 `lint:ci`, `typecheck:ci`, 관련 smoke/E2E 중 가능한 검증을 통과해야 완료로 본다.

## 단계별 계획

| 단계 | 범위 | TOP 30 항목 | 상태 |
|---|---|---|---|
| 1 | 라우트 보호, 포털 404, 더미 지표, Edge Function 내부 호출 보호 | 1, 2, 3, 4, 5, 10, 11, 13, 15 | 완료 |
| 2 | API 검증/응답 표준화와 권한 세분화 | 6, 7, 8, 14, 16, 21, 22, 23 | 진행 중 |

| 5 | 운영 관측성, 배포/마이그레이션 문서, 장기 유지보수 | 19, 28, 29, 30 | 예정 |

## 1차 배치 완료 기준

- `/global-fulfillment` 계열 페이지가 인증 없이 열리지 않는다.
- `/global-fulfillment/admin/*`는 관리자 권한으로 한 번 더 제한된다.
- `/portal/dashboard`가 실제 페이지로 존재해 로그인/포털 내비게이션이 404를 만들지 않는다.
- 글로벌 풀필먼트 홈은 더미 통계 대신 API 응답만 표시한다.
- CS Edge Function은 서버와 Edge Function 양쪽의 `ANH_EDGE_INTERNAL_SECRET`가 일치해야 실행된다.
- 1차 변경 파일이 `lint:ci`, `typecheck:ci` 범위에 포함된다.

## 다음 배치 후보

1. `SAMPLE_` 기반 운영 화면을 기능 플래그 또는 “준비 중” 화면으로 전환한다.
2. 공유 링크 API의 만료/감사 로그/권한 정책을 점검한다.
3. 입고-검수-재고반영-주문 핵심 E2E를 CI smoke 후보로 승격한다.
4. `app/api/global-fulfillment/*` 나머지 route에도 전용 permission과 Zod 검증을 확장한다.
5. Edge Function 내부 호출 시크릿을 배포 환경에 설정하고 CS smoke를 추가한다.

## 2차 배치 진행 기준

- 글로벌 풀필먼트 주문 목록/생성 API는 전용 permission을 사용한다.
- 주문 생성 API는 Zod 스키마로 필수값, UUID, 문자열 길이를 검증한다.
- 주문 목록 API는 기본 조회 제한을 둬 무제한 전체 조회를 피한다.
- 글로벌 풀필먼트 통계 API는 필요한 컬럼만 조회한다.
- 권한 매핑과 사이드바 노출 조건이 같은 permission을 기준으로 동작한다.

## 3차 배치 진행 기준

- 글로벌 풀필먼트 예외 목록/생성 API는 전용 permission을 사용한다.
- 예외 생성 API는 Zod 스키마로 필수값, UUID, 심각도, 문자열 길이를 검증한다.
- 예외 목록 API는 기본 조회 제한을 둬 무제한 전체 조회를 피한다.
- 샘플 데이터 기반 글로벌 풀필먼트 관리자/예외 화면에는 명확한 경고 배너를 표시한다.
- 샘플 데이터 경고 컴포넌트와 적용 화면이 `lint:ci`, `typecheck:ci` 범위에 포함된다.

## 4차 배치 진행 기준

- 샘플 데이터 기반 글로벌 풀필먼트 작업 화면에는 명확한 경고 배너를 표시한다.
- 상품 준비, Wave 관리, 2차 정렬, 검증/검사, 패키지 검증, 무게 측정, 반품, 마감 시간 화면을 우선 포함한다.
- 경고 문구는 실제 출고, 검수, 운임, 환불, 고객 대응 판단에 사용하지 말아야 한다는 리스크를 직접 설명한다.
- 적용 화면이 `lint:ci`, `typecheck:ci` 범위에 포함된다.

## 5차 배치 진행 기준

- 포털 레이아웃은 하드코딩된 사용자명/이메일 대신 Supabase 세션과 `user_profiles` 정보를 표시한다.
- 세션이 없거나 프로필이 없을 때도 안전한 기본 문구를 표시한다.
- 물동량 공유 링크는 실제 데이터 조회 성공 시 `last_accessed_at`를 갱신한다.
- 포털 레이아웃과 공유 API 변경 파일이 `lint:ci`, `typecheck:ci` 범위에 포함된다.

## 6차 배치 진행 기준

- 물동량 공유 링크 생성 API는 `customer_id`, `date_from`, `date_to`, `expires_at`, `password`를 명시적으로 검증한다.
- 만료일이 없는 공유 링크는 기본 7일 만료로 생성한다.
- 공유 링크 만료일은 최대 30일 이내로 제한한다.
- 공유 링크 비밀번호는 입력 시 8자 이상, 128자 이하로 제한한다.
- 공유 링크 조회/삭제 API는 UUID 형식을 검증한다.

## 7차 배치 진행 기준

- 입고 공유 링크 조회/생성/수정/삭제 API는 `receipt_id`, `id`, `expires_at`, `password`, `language_default`를 명시적으로 검증한다.
- 만료일이 없는 입고 공유 링크는 기본 7일 만료로 생성한다.
- 입고 공유 링크 만료일은 최대 30일 이내로 제한한다.
- 입고 공유 링크 비밀번호는 입력 시 8자 이상, 128자 이하로 제한한다.
- 입고 공유 링크 요약 필드는 언어별 2000자 이하로 제한한다.
- 입고 공유 링크 API 변경 파일이 `lint:ci`, `typecheck:ci` 범위에 포함된다.

## 8차 배치 진행 기준

- 글로벌 풀필먼트 드롭시핑 시뮬레이션 화면에는 실제 입고/재고/송장 처리 결과가 아님을 명확히 표시한다.
- 일반 어드민/관리/운영 샘플 화면에는 실데이터 오인 방지 경고를 표시한다.
- 관리자 홈, 관리자 알림, CS 성과, CS 담당자, 관리팀 대시보드, KPI, 관리팀 재고, 다수지, 포장 관리 화면을 우선 포함한다.
- 경고 문구는 실제 운영 보고, 성과 평가, 고객 안내, 출고/포장 판단에 사용하지 말아야 한다는 리스크를 직접 설명한다.
- 적용 화면이 `lint:ci`, `typecheck:ci` 범위에 포함된다.

## 9차 배치 진행 기준

- Supabase 생성 타입에 `inventory_volume_share.last_accessed_at` 누락을 반영한다.
- 공유 링크 접근 이력 업데이트 코드가 untyped 우회 없이 타입체크를 통과한다.
- Vercel/서버/Supabase Edge Function 환경변수 체크리스트를 문서화한다.
- 비로그인 사용자의 글로벌 풀필먼트 API 접근 차단 테스트를 추가한다.
- `/global-fulfillment`, `/portal/dashboard` 비로그인 라우트 보호 테스트를 추가한다.
- 인증된 관리자 환경에서 공유 링크 생성 입력 검증 테스트를 조건부로 추가한다.
